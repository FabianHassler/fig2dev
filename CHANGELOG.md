# Changelog

## Unreleased

- JPEG DCT passthrough (audit pass 19): eps/ps/pstex embed a JFIF or Exif JPEG as genps does, without decoding it: `AnalyzeJPEG` reads size, components and the Adobe marker, and `JPEGtoPS`'s EPS wrapper (`/DCTDecode`, `/Decode`, the CMYK Adobe inversion, `%%Creator: jpeg2ps by Thomas Merz in fig2dev 3.2.9a`) carries the file's bytes ASCII85-encoded as encode.c writes them; readjpg.c's messages ("unexpected end of JPEG file!", "DNL marker not supported...", "unknown color space") precede "NAME: Bad JPEG format". The block equals the reference's on all 15 test JPEGs with a data block (before: 0, the pixels were written as hex), the messages on the 8 error cases. C loops forever on a file without a further marker; here it is an "unexpected end" error. PDF and the bitmap languages still draw decoded pixels.
- Picture reading as the C readers do (audit pass 18): PNG always through the `read_png` port (file palette order, libpng's gamma/composition arithmetic with `gAMA`, `bKGD` and `-g`, `tRNS` as `num_transp`/`transp_cols`, libpng's warning and error lines, interlace warning), GIF through the `gif` crate with the transparent colour found again in the colour map (`Pic.transp_cols`), PCX/XBM/PPM as literal ports of readpcx.c/readxbm.c/readppm.c (C's scanline, padding and end-of-data quirks), XPM `None` black and no transparency, GIF/PPM/TIFF/XPM as PCX pictures, `pic_type` as genps's table (no P1-P5, no JPEG without JFIF/Exif), failures as "NAME: Bad TYPE format". Image data, palette and stderr equal the reference on 109 of 128 test pictures (before: 46 of the first 110); the rest are the reference's crashes and external-tool noise, 16-bit gamma rounding and palette TIFFs. EPS: a colour-keyed picture writes the key for its transparent pixels (a non-white key never masked).
- Header metadata (audit pass 16): eps/ps write `%%Title` (`-n`, else the input name, else stdin), `%%Creator: fig2dev Version 3.2.9a`, `%%CreationDate` (`SOURCE_DATE_EPOCH`, else UTC now), `%%Magnification`, the `%%DocumentNeededResources` CMap lines for non-ASCII text and the whole-figure comments before the prolog, in genps's order (no `%%HiResBoundingBox`/`%%LanguageLevel`); svg writes gensvg's preamble, Creator/CreationDate/Magnification comments, `<svg>` with `width`/`height` in points, `<desc>` comments and the `<g fill="none">` wrapper; pdf has an Info dictionary (Title, Creator, Producer, CreationDate, ModDate). Header blocks equal fig2dev's on 311/311 fixtures and sample figures (tests/header_meta.rs).
- Split out of the RustFig repository with its history: crates `figbase` and `fig2dev` (library) and the `fig2dev` program (package `fig2dev-cli`).
- FMA parity with the reference binary (audit pass 12): `ellipse_bound` (2 fused ops), `arc_bound` radius and trans_spline (blend functions, point weights, float step angle) fuse `a*b+c` as clang does; exact against oracle programs on 412,800 ellipses and 20,000 splines (tests/fma_oracle.rs). The "closed spline with less than three points" message has no newline, as in C.
